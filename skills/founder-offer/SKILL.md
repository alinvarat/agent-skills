# Founder offer

1. Read existing `founder/idea.md`, `pitch.md`, `numbers.json`, `board.md` and relevant buyer/competitor evidence. Read the Offers section of [framework lenses](../founder-board/lenses.md); it is a summary, not its author’s personal advice.
2. List supported obstacles before, during and after purchase. Map each to a useful deliverable, service, format or guarantee. Compare buyer value and delivery cost; keep valuable, affordable items. Do not force a fixed number of objections or bonuses.
3. Define core outcome, useful bonuses, honest guarantee, clear offer name and genuine urgency/scarcity if any. Cost guarantees using an explicit claim-rate assumption before promising them. Score outcome, confidence, time and effort before/after; explain what changes each score.
4. Write `founder/offer.md` with obstacles, stack, costs, scores and evidence gaps. keep established prices and never add discounts without the user’s decision. No fake proof, scarcity, reference prices or claims.
5. Before replacing `founder/pitch.md`, preserve the old pitch and entire panel run under a unique version/timestamp. Never overwrite an earlier baseline. If re-testing is requested, use founder-consumer with matching customer profile, seed and sample size but a fresh run/answers. Compare answered/missing counts and objections. A 20-person run is comparable only with a matching baseline.

Done: the new pitch matches deliverable promises and costs. If re-testing is not requested or delegation is missing, mark it pending instead of inventing results. Simulated improvement is not measured conversion lift. Do not change public offers or run a complete launch automatically.
