# Founder launch

1. Read the brief and available `founder/numbers.json`, `ops.md`, `brand.md` and `marketing.md`. Use existing decisions; label missing lead times or dates.
2. Design the cheapest relevant real demand test before major spending: priced waitlist/preorder, pop-up, paid pilot or founding-member offer. Define success, deadline, price and denominator before running it. A planning request creates plans/drafts only; contacting buyers, publishing, accepting orders or paying needs an explicit request for that action.
3. Build the countdown using real dates in the user’s timezone. Use the stated launch date; otherwise label a realistic provisional date. Each task needs owner, deadline and dependencies. Cover permits/money, build/suppliers, brand assets, channels, staffing/training and soft open. Mark the critical path.
4. Write an hourly launch-day run sheet: roles, channels/messages, approved offer and fallback for failures.
5. Define first-month checks: units/day versus break-even, channel metrics, change thresholds and reviews on days 7, 14 and 30. Compare real-test and simulated rates only for the same offer and known denominators. Trust real behavior over simulated predictions.

Done: `founder/launch.md` contains the test, countdown, run sheet and review plan. Verify date order and dependencies; mark assumptions and blocked tasks. Keep approved prices; Discounts require the user’s decision. The plan does not itself authorize external execution or another complete Founder workflow.
