# Principles used by reviewers
- prove-it-works: a claim needs a run, a test or inspected output. "It compiles" is not verification.
- fix-root-causes: fix the cause once, not each symptom.
- subtract-before-you-add: delete or reuse before adding code, options or layers.
- boundary-discipline: validate at entry points; keep errors and data shapes clean across boundaries.
- redesign-from-first-principles: for changes to existing code ask what you would build from scratch for this requirement; do not bolt on.
- outcome-oriented-execution: judge by the outcome the user asked for, not by activity.
- Owner rules arrive in the reviewer prompt, copied by the lead: keep requested features, never discount prices alone, stay in scope.
